# 三种模式与模型切换

## 页面操作

首页和项目对话输入框下方都有两个下拉框：

1. 输入模式：构建应用、对话问答、图像生成。
2. 选择模型：显示该模式的模型白名单。

每种模式分别记住上次选择的模型；任务开始后锁定模式和模型，防止本次任务被中途切换。历史消息显示实际使用的模型 ID。

- **构建应用**：按需求生成或修改前端页面、Java等后端工程源码，校验成功后创建版本。静态三文件页面可预览，后端工程在代码面板查看、下载后本地运行。
- **对话问答**：保存问题和回答，并携带近期成功问答的上下文；不生成文件、不创建版本。上下文最多20条消息、约24000字符，构建任务和图像任务不会混入问答上下文。
- **图像生成**：每次生成一张1024×1024图片，保存到当前项目，可在消息和右侧“图片”标签查看、下载。图片不会自动插入应用源码。当前为文生图，不包含参考图上传或图像编辑。

## 推荐配置

| 模式 | 默认配置 | 可切换模型 | 用途 |
|---|---|---|---|
| 构建应用 | 沿用 `atoms.model.name` | `qwen-plus`、`qwen3-coder-plus`、`qwen3-coder-flash` | 通用生成，或选择专门的代码模型 |
| 对话问答 | `qwen-plus` | `qwen-plus`、`qwen-flash` | 需求讨论、知识问答 |
| 图像生成 | `qwen-image-2.0` | `qwen-image-2.0`、`qwen-image-2.0-pro` | 2.0侧重效果与速度平衡，Pro侧重细节与文字渲染 |

模型列表是配置白名单，不表示账号已经开通所有模型。实际可用模型以当前阿里云地域、业务空间、API Key权限和余额为准。不要把翻译模型 `qwen-mt-lite` 用于应用生成。

官方资料：[文本模型](https://help.aliyun.com/zh/model-studio/text-generation-model/)、[Coder模型](https://help.aliyun.com/zh/model-studio/qwen-coder)、[图像模型与同步接口](https://help.aliyun.com/zh/model-studio/qwen-image-api)。

## 配置文件

所有模型配置统一放在 `atoms.model` 节点下，图像配置为其下的 `image` 子节点。本地直接编辑 `backend/config/application-private.yml`（不上传Git），已填写的文本模型地址与密钥继续沿用。新增部分如下：

```yaml
atoms:
  model:
    # 原有 base-url、api-key、name 保留，不要重复添加 model 节点
    timeout-seconds: 300
    max-output-tokens: 16000
    build-models: qwen-plus,qwen3-coder-plus,qwen3-coder-flash
    chat-default: qwen-plus
    chat-models: qwen-plus,qwen-flash
    image:
      endpoint: ""
      api-key: ""
      default-model: qwen-image-2.0
      models: qwen-image-2.0,qwen-image-2.0-pro
      size: 1024*1024
```

`atoms.model.name` 是构建模式的默认模型，`chat-default` 和 `default-model` 分别是对话、图像默认模型。修改白名单后重启后端，刷新前端即可选择。

图像的 `api-key` 留空时复用文本模型密钥。同一个阿里云百炼 API Key 可以在具备相应权限时调用文本和图像模型，不需要另一家供应商的 Key；文本与图片费用分别计量。

图像的 `endpoint` 留空时，后端从文本地址推导同域名的阿里云原生接口：

```text
文本：https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
图像：https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation
```

图像不是通过 `/chat/completions` 调用。若文本使用自定义网关，请手动填写 `atoms.model.image.endpoint` 为完整原生图像接口，必要时单独填写图像密钥；目前图像协议支持阿里云同步文生图接口，不能只换模型名就使用任意图像供应商。

图片先从供应商 OSS 临时链接下载，再以二进制存入 `image_assets` 表，因此不会因临时链接过期丢失。单图限制8MB，图片接口校验项目归属，浏览器仅请求本地图片接口，不获得 API Key。

## 启动与数据兼容

在 IDEA 重启 `AtomsApplication`，或：

```bash
cd backend
mvn spring-boot:run
```

启动时自动增加 `run_options`、`message_details`、`image_assets` 三张表，不删除或重建原有业务表。旧项目、消息、代码版本仍可读取；旧消息默认归类为构建消息。

本地演示可使用 `local` profile，问答与图片均明确标记为演示。无需单元测试。

## 手动验收

1. 选“对话问答 / qwen-plus”，告诉助手一个昵称，再追问昵称是什么，检查多轮上下文。
2. 切换“qwen-flash”继续问答，检查新消息显示新模型，旧消息仍显示原模型。
3. 切换“图像生成 / qwen-image-2.0”，输入画面描述，等待消息与图库出现图片。
4. 刷新页面，检查图片仍可查看；下载原图，确认文件可打开。
5. 在已有代码版本的项目中问答和生图，确认版本号不变。
6. 切回“构建应用”并选择已获授权的模型，发起修改，确认新建代码版本。
7. 如果模型未开通或额度不足，应显示明确错误，不覆盖已有代码或图片。

## 请求超时与输出长度

`atoms.model.timeout-seconds` 控制单次文本模型请求等待上限，默认300秒。一次构建可能包含计划、生成、修复等多次调用，因此总任务时间可能超过单次上限。`max-output-tokens` 默认16000，须处于所选模型支持的范围；达到输出上限时会明确提示，不保存可能被截断的工程。较大工程建议按模块分次生成。

超时、域名解析失败、连接中断、TLS错误和无效响应分别显示提示。后端记录任务ID、模式、模型及异常类型，不记录API Key或需求正文。

## 上传GitHub后的配置位置

本地配置：`backend/config/application-private.yml`；服务器配置：`backend/config/application-production.yml`。两者均不进入Git，模型选项仍集中在同一个 `atoms.model` 节点。仓库中的 `backend/src/main/resources/application.yml` 只含公开默认值。新机器按 `backend/config/application-production.example.yml` 创建服务器配置即可。
